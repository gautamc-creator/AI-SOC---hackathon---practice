# VIGIL demo cue sheet

## Primary 90-second path

1. Open the saved Elastic dashboard on the fixed 16-minute time window.
2. Point to the explicit synthetic-data warning before showing any number.
3. Show 12 evidence events, ₹11,60,000 suspicious UPI fixture total, and five affected accounts.
4. Open the ES|QL query or prepared query card; highlight the `LOOKUP JOIN` between security evidence and bank context.
5. Show the Attack Discovery lead and the deterministic unsupported-certainty check.
6. Open the workflow execution. Show the case, three attached alerts, and the human gate.
7. Select `hold` in a fresh rehearsal only. Do not approve a destructive action.
8. Run the genuine ledger verifier, then the tampered-ledger verifier.
9. Return to the dashboard and close on “Evidence before conclusions.”

## Before walking on stage

- Pin the dashboard time window; disable auto-refresh.
- Keep Kibana, terminal, repository README, and the backup video in that tab order.
- Use synthetic IDs only; close email, AWS billing, connector secrets, and personal tabs.
- Confirm the AWS-hosted LLM path is genuinely in the judged runtime before mentioning it.
- Confirm whether a backup video is permitted.
- Confirm pitch and Q&A duration.
- Record the exact Elastic version and model/connector IDs used during the event.

## Failure branches

| Failure | Recovery line and action |
|---|---|
| Live Elastic is slow | “The same frozen scenario is available in our recorded run; I’ll continue with the evidence outputs.” Play only if organizers permit. |
| Attack Discovery times out | Show the saved discovery and its execution ID, then continue to the deterministic guardrail and gate. |
| LLM call fails | State that the workflow fails closed; use the captured AI output and continue with deterministic evidence. |
| Workflow resume fails | Show the previously completed execution and the case comment recording `hold`. |
| Network is unavailable | Run `make demo` locally to show the draft and pass/fail ledger verification. |
